# Реестр проектов

Тестовое приложение на React, TypeScript и Vite. Оно загружает JSON с 2 000 демонстрационных проектов, показывает ход загрузки и позволяет прервать запрос. После загрузки доступны виртуализированная таблица и поиск по всем её колонкам.

## Локальный запуск

Понадобится Node.js 24 и npm.

```bash
npm ci
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). Загрузка начинается при открытии страницы.

## Запуск в Docker

Понадобится работающий Docker с Compose v2.

```bash
docker compose up --build
```

Адрес приложения тот же. Контейнер запускает dev-сервер Vite, а изменения в `src/` и `index.html` подхватываются с хоста. После изменения зависимостей, настроек сервера или набора данных запустите команду с `--build` повторно.

Остановить контейнер можно командой `docker compose down`.

## Как проверить

1. Откройте страницу. В dev-режиме загрузка занимает около 2,4 секунды. Полоса отражает долю полученных байтов. После успешной проверки файла появится отметка «Загружено · 100%».
2. Перезагрузите страницу и нажмите «Отменить загрузку». Таблица не появится. Нажмите «Загрузить снова», чтобы начать новый запрос.
3. После загрузки прокрутите таблицу до проекта с ID 2000. Заголовок остаётся на месте. В инспекторе DOM видны только строки вокруг текущей области просмотра и служебные строки, сохраняющие высоту прокрутки.
4. Введите `кАзАнЬ`, `ремонт` или `2000`. Через 300 мс после последнего изменения останутся подходящие записи, а совпадения будут подсвечены. Запрос `.` ищет буквальную точку. Очистка поля возвращает полный список.
5. Чтобы проверить ошибку сети, заблокируйте `/data/projects.json` в инструментах разработчика и обновите страницу. Снимите блокировку и нажмите «Загрузить снова».

```bash
npm run lint
npm run build
npm run preview
```

`preview` отдаёт файл из сборки с обычной скоростью. Для проверки прогресса в этом режиме включите ограничение скорости сети в инструментах разработчика.

## Структура и решения

```text
src/
  App.tsx                     Компоновка страницы
  index.css                   Базовые стили и переменные темы
  shared/http/                Запросы Fetch, чтение ответов и прогресс по байтам
  features/catalog/
    ProjectCatalog.tsx         Компоновка каталога
    projects.ts               Тип проекта и колонки
    download/                 Запрос, проверка данных, хук и панель загрузки
    search/                   Поле поиска и хук фильтрации
    table/                    Разметка таблицы и хук виртуализации
public/data/projects.json     Демонстрационный файл
server/demoCatalog.ts         Потоковая отдача файла в Vite dev
scripts/generate-catalog.mjs   Детерминированный генератор записей
```

- **HTTP.** `request` из `src/shared/http` принимает параметры Fetch, `query` для параметров URL и `json` для отправки JSON. При каждом вызове укажите `responseType`: `json`, `text`, `blob`, `arrayBuffer`, `stream`, `void` или `raw`. JSON возвращается как `unknown` для последующей проверки. `onProgress` получает прочитанные байты и общий размер или `null`, если размер неизвестен. В режиме `stream` прогресс обновляется по мере чтения потока. Режим `raw` возвращает исходный `Response` при любом HTTP-статусе. В остальных режимах неуспешные HTTP-статусы приводят к `HttpError`, а сбои запроса и чтения — к `RequestError`.
  Для тела запроса укажите одну опцию: `body` или `json`. `onProgress` доступен для форматов, в которых HTTP-модуль читает тело ответа, включая `stream`.
- **Загрузка каталога.** `loadProjects` запрашивает JSON через `request`, переводит полученные байты в проценты и передаёт результат в `parseProjects` для проверки полей и уникальности ID. Если размер ответа неизвестен, индикатор показывает неопределённый прогресс.
- **Состояния запроса.** `useProjectDownload` запускает загрузку и управляет прогрессом, отменой и повтором. При отмене или размонтировании он прерывает запрос через `AbortController` и игнорирует его поздние результаты.
- **Поиск.** `useProjectSearch` применяет запрос через 300 мс после последнего изменения. Для фильтрации и подсветки используется один шаблон поиска буквальной подстроки без учёта регистра. Компонент выделяет совпадения через `<mark>`.
- **Виртуализация.** TanStack Virtual рассчитывает диапазон видимых строк и небольшой запас вокруг него. Библиотека не навязывает разметку. Это позволяет сохранить `<table>`, заголовки колонок и абсолютные номера строк для вспомогательных технологий. Фиксированная высота строк позволяет рассчитывать смещения без измерения каждой ячейки. Табличные данные могут прокручиваться горизонтально на узких экранах. Модель колонок для этого задания описана типизированным списком, поскольку таблице нужны только вывод и общий поиск. [Документация TanStack Virtual](https://tanstack.com/virtual/latest/docs/api/virtualizer)
- **Демо-сервер.** Файл лежит в `public/` и доступен по HTTP как в dev, так и после сборки. В dev Vite отдаёт тот же файл частями и завершает передачу при отключении клиента. Это делает отмену воспроизводимой на локальной сети. Чтобы пересоздать набор данных, выполните `npm run data:generate` и перезапустите dev-сервер. В Docker пересоберите образ.
- **Стили.** CSS Modules лежат рядом с интерфейсом каждой части каталога. В `index.css` находятся базовые правила страницы и переменные темы.

Виртуализация ограничивает количество элементов в DOM. Полный JSON и результаты фильтрации остаются в памяти браузера. При росте набора до объёма, который неудобно передавать целиком, адаптер данных можно заменить на API с серверным поиском и постраничной загрузкой.
